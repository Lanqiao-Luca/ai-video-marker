**目的**：围绕一个明确问题做有限修订，保留有效镜头和已确认基线。

# 镜头迭代

接[Loop入口](README.md)的任务输入。每轮先在已有计划中定位唯一主要问题、具体时点/版本、预期变化和不应变化的范围，再把当前轮交[原制作Workflow](../workflows/README.md)。

流程为：用户/真实检查差异 → 定位首个受影响阶段 → 只修该范围 → 核同版本必要技术/可看对照 → 收回实际结果、费用、产物身份和剩余预算。

一次明确问题可先做一轮，仍不收敛再有限追加；两轮只是建议起点，按当前授权和实际成本填写。恢复后沿累计次数继续，不因换窗口清零。未知结果先查现存输出，避免重复付费调用。

| 退出状态 | 依据及去向 |
|---|---|
| ACCEPTED | 用户实际采用对应版本/范围，回主流程整合，并核相交接缝 |
| REVIEW_PENDING | 必要正确性检查完成，有可审候选，创作判断未发生 |
| REWORK_REQUIRED | 有具体可定位问题且预算允许，回首个受影响阶段 |
| BLOCKED | 必要输入/能力/授权不可得，记录恢复条件，独立工作可继续 |
| STOPPED | 预算耗尽或用户叫停，保存有效前缀和未决，不自动续轮 |

正确性失败不能借REVIEW_PENDING让用户代找错；技术通过不自动改为ACCEPTED。实际位置改变先经原Workflow更新输入/输出绑定；收束交真实产物和过程归属。循环记录见[执行与接续合同](../templates/project/README.md)，本页没有计费拦截器、调度器或自动重试服务。
