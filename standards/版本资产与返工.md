# AN06 版本资产与返工

**输入**：当前产物、用户反馈、依赖素材、变更目的与已确认基线。

**动作**：
1. 每个作品用README标出当前认可版本、待审候选、关键源资产和下一步，不把“最新文件”自动当正式采用。
2. 按[AP04](./写入与原件边界.md)核原件身份，登记素材/版本的来源、用途、采用关系与适配差异。
3. 具体问题退回最近受影响步骤，保留未变化的已认可镜头。主体外观与采用基线遵循[AP05](./已确认基线保护.md)。
   涉及动画/渲染修改时，在既有镜头/版本记录列本次“变更输入→受影响片段/接缝→需重算或可复用产物及依据”；段ID、时间范围、资产/脚本/参数/声音cue身份和输出路径须能追到真实制作调用。优先沿现有镜头或渲染段粒度复用；尚无分段能力时如实记实际重算范围，不为声称局部返工另建渲染引擎。
   范围按实际依赖判断：关键帧/姿态变化核与它相连的插值、运镜及转场；台词/声音长度变化核覆盖段、字幕/音效cue与后续偏移；共享资产、引擎或后期设置变化核全部实际消费者。作者案例中“两张关键帧间一段、改一帧重渲两侧”仅在本片真实依赖也成立时选用，不能固定套用。复用须核输入及参数身份、时间基准、随机种子/缓存（有时）、拼接编码与声音接点仍兼容；未知依赖先核或扩大相交重算，不能把旧缓存当当前结果。重渲后按[AN07](./制作验证与阶段验收.md)核实际受影响段及接缝，发现沿[AN08](./审核交接与定向复核.md)闭环；未失效证据继续复用。
4. 产出可看对照，按[AP03](./证据与结论.md)登记已实施、技术通过、用户采用及待审状态。
5. 作品验收后返回作品归档请求，具体记录按[结果交接接口（见本层返回接口）](<README.md#return-context>)抽取可复用经验；只有证据支持的范围进入领域标准。

**输出**：当前状态、变更/采用记录、局部返工范围、来源映射和保留版本。

**验收**：可以找到认可原件、被拒原因和当前运行输入；下一位助手无需读完整聊天也能继续；必要域内交付与原件/过程外归属符合[RET01](./项目留存与过程清理.md)，外置来源可按SHA/位置账本定位并在绑定域外工作区恢复，不再把全部必要原件长期位于项目目录内当验收条件。文档目的与迁移约束分别引用[AP01](./目的守恒.md)、[AP04](./写入与原件边界.md)；当前任务及运行平台的实际约束继续适用。

**失败出口**：原件或采用关系不明先标未知；不覆盖、静默清理或凭同名推断身份。
