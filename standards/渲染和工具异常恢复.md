**目的**：在渲染或工具故障后找准首个断点，保留有效输入与结果，并在授权和预算内恢复原制作目标。

# AN09 渲染和工具异常恢复

**输入**：未完成验收点、原失败阶段、当前目的、真实错误和日志、最近可信输入/脚本/配置/环境版本、已发操作、现存输出以及明确写集与预算。

**触发/适用条件**：当前必要制作或验证停在输入、环境、配置、渲染、编码或结果未知；只恢复本次真实失败，不为文档接入主动触发渲染。

**共用原则**：[AP01](./目的守恒.md)、[AP02](./复用与影响边界.md)、[AP03](./证据与结论.md)、[AP04](./写入与原件边界.md)、[AP05](./已确认基线保护.md)。

## 先定位首个有证据的断点

按“输入→工具环境→配置与取样→渲染→编码/合片→读取输出”有界排查，不因一个末端报错重生成全部素材：

| 断点 | 最小核对与可用修法 | 不能据此推出 |
|---|---|---|
| 输入缺失或身份不符 | 核相对路径、真实文件/哈希、采用版本、配置引用；从域内已授权真实来源恢复必要输入，保留来源 | 不凭同名选文件，不捏造缺失原画、历史脚本或已采用事实 |
| 字体、FFmpeg/FFprobe或Python包 | 核实际可执行文件、版本/能力、包与字体路径；复用已可用工具或显式本项目参数，判断替代路径能否保留原验收 | 工具缺失不授权跨域安装、改全局环境、绕权限或把文字显示缺失当作品通过 |
| 配置、裁切与空间取样 | 核尺寸、坐标/单位、关键帧、裁切范围、阶段参数和真实消费者，先对照受影响画面 | 数值合法不等于角色好看；不能以改主体基线掩盖裁切或取样错误 |
| 编码、音轨、色彩与合片 | 核错误日志、流映射、时长、帧率、编码能力、像素/颜色范围与音轨来源，读回真实输出并解码 | 退出码0、容器存在或贴色彩标签不证明声画、矩阵或同步正确 |
| 部分输出或结果未知 | 先查现存文件、帧数/时长、流信息及必要解码，区分已完成、失败段、半成品与不明；保护有效结果 | 未知不直接重放同一动作或覆盖文件，半个文件不能当可复用的已通过镜头 |

## 受控恢复并返回原阶段

1. 在作品原记录保留日志、首断点、输入/操作身份、选择与排除理由、允许改点、预期读回和原恢复阶段。先核现有能力，缺入口时才在明确写集内补最小本地解析/转换适配；本方法不意味着本轮已新建工具。
2. 缺前置时只从真实且获准来源补所缺部分；临时占位或模拟输入明确标记，只证明其下游，不冒称完整正常制作链路。输入不足以满足本轮目标时保留缺口，不制造成功产物。
3. 结果未知先核状态；确认可安全重跑后在新候选或新输出目录运行最小失败段，不覆盖采用版、不影响并行任务。已成立且未失效的前置和镜头继续复用，不换身份从头重做。
4. 重跑后按[AN07](./制作验证与阶段验收.md)做必要元数据读回、解码、声画/接缝或实际听看；工具恢复只证明工具可用，原验收点满足后才回原失败阶段继续。发现审核问题按[AN08](./审核交接与定向复核.md)交接。
5. 复用当前loop/workflow和用户给定的有限次数、时间/成本预算；记录每次真实进展，无新证据或预算已到时停在可信基线并给恢复条件，不无限换工具。

**停止与边界**：必要外部输入、真实权限、工具能力或预算不可得时，冻结依赖该条件的动作，说明具体缺口并继续独立可做部分；找不到现成脚本不自动等于所有路径耗尽。不能自动跨域安装/改全局配置，不复制生产调度或数据库恢复动作，也不能把受阻所需授权视为已获准。

**输出与验收**：首断点及证据、最小差异/新增输入、实际操作与读回结果、复用/失效范围、剩余问题和原流程恢复点。恢复成功必须回到原目标的相应验收；未执行的动作保持未执行。
